操作系统与 Linux 内核
==========================================

想象用户程序提交了一个设备请求，随后睡眠，直到硬件完成。画一条时序线，在每个函数旁标出谁在运行、能否睡眠、谁持有请求对象。

从系统调用到完成通知
----------------------------

1. 用户线程通过系统调用进入内核。设备接口检查输入与长度，把异步操作需要的状态保存在寿命足够长的对象里。普通用户态指针不能直接当成长期有效的内核或 DMA 地址。
2. 驱动提交工作。线程可在允许睡眠的上下文中用等待队列或 completion 等待。描述等待条件时要考虑“通知先于等待”以及超时后的对象所有权。
3. 设备发出中断。硬中断处理确认来源，按硬件协议确认或屏蔽中断，将可延后且可能睡眠的工作放在线程化中断或工作队列。随后发布完成状态并唤醒等待者。 `Linux 通用中断处理 <https://docs.kernel.org/core-api/genericirq.html>`_
4. 请求成功、取消、超时或设备移除时，都可能有回调在途。画出阻止新请求、等待在途访问结束、释放缓冲区的顺序，并标注哪些等待可能与回调所需的锁相冲突。

要能解释的内核机制
----------------------------

* **调度与并发。** 进程与线程、上下文切换、抢占、硬中断与线程上下文。解释 CPU 跑满、线程阻塞、已唤醒但未获调度三类延迟如何区分。
* **同步。** mutex、spinlock、atomic、引用计数、等待队列与 completion 各自保护什么。说明临界区是否允许睡眠、中断是否也会访问同一状态，以及锁顺序。内核配置会影响锁的语义，尤其是 PREEMPT_RT。 `Linux 锁类型与上下文约束 <https://docs.kernel.org/locking/locktypes.html>`_
* **内存管理。** 用户和内核虚拟地址、物理页、页表和缺页。比较 kmalloc 与 vmalloc 的连续性，理解分配标志和睡眠约束。设备可访问性、DMA 地址与缓存属性需要按 DMA API 另外确认。 `Linux DMA 映射指南 <https://docs.kernel.org/core-api/dma-api-howto.html>`_
* **驱动模型。** 设备枚举、匹配、probe、remove、依赖未就绪时的延期探测，模块加载与卸载。能从 sysfs 绑定关系、内核日志和资源信息解释“模块已加载但设备没工作”。 `Linux 平台设备与驱动 <https://docs.kernel.org/driver-api/driver-model/platform.html>`_

自测与解题提示
----------------------------

**中断计数增长，但提交方仍然等到超时。你先区分什么？** 先确认增长来自目标设备和目标请求。记录中断状态、处理程序读出的请求标识、完成状态发布时间、唤醒与调度时间。共享中断、确认次序、匹配错队列和线程调度延迟分别对应不同证据。

**退出路径持锁并等待工作队列清空，偶发卡住。你会画什么？** 画出关闭线程持有的锁、它正在等待的工作项，以及工作项完成所需的锁。若成环，先设计一个拒绝新工作的状态，再安排释放锁、同步在途回调与销毁对象的次序。
